# 超级工作台设计：统一应用门户与小红书接入

- 日期：2026-11-09
- 阶段：设计已在对话中确认；本文待用户审阅，通过后再编写实施计划
- 首期范围：超级工作台框架 + 小红书运营应用

## 1. 目标与硬约束

在当前工程上增加统一业务应用入口。用户使用现有账号登录，先选择应用，再进入对应工作台。首期只有“小红书运营”一个真实应用，但仍显示应用选择页，不自动跳过。

必须遵守：

1. 沿用现有技术栈、依赖和部署方式，不引入微前端、新后端服务或新框架。
2. 复用现有认证与用户数据隔离，不另建登录系统，不新增角色、菜单权限或应用授权后台。
3. 保留小红书所有现有功能。不得修改小红书业务页面、接口、数据库结构、数据范围、采集发布流程或定时任务。
4. 变更只作用于统一入口、前端应用注册、外围路由组织、登录后的导航及工作区返回入口。
5. 本次不实现其他业务应用，不以虚假应用卡片或原社交平台占位项充当已接入应用。

## 2. 现有工程事实

### 技术栈

- 前端：React 19、TypeScript、Vite、Ant Design 6、React Router 7、Axios。
- 后端：FastAPI、SQLAlchemy、Alembic；认证使用现有密码校验与 access/refresh token。
- 用户模型目前包含账号、密码哈希与创建时间；尚未发现角色、应用授权或菜单权限体系。

### 现有结构

- `/login`：登录与注册页面。
- `/platform-select`：受登录保护的社交平台选择页。
- `/platforms/xhs/*`：现有小红书业务路由。
- `/tasks`、`/models`、`/settings`：现有共享外壳下的任务中心、模型配置、设置。
- `AppShell`：小红书固定菜单、主题切换、通知、用户信息及退出入口。
- `ProtectedRoute` 与 `PublicOnlyRoute`：现有登录守卫。
- 笔记发现与数据抓取通过现有 KeepAlive 配置保留页面状态。
- 当前登录页会优先跳转到 `location.state.from`，否则跳转 `/platform-select`；新设计需要明确覆盖该导航行为，但不改认证实现。

当前工作目录不是 Git 仓库；本文保存到本地，不自动初始化 Git 或创建提交。

## 3. 方案选择

采用“同一工程内轻量应用注册”，不采用仅重命名平台选择页或微前端拆分。

- 仅重命名平台选择页：改动少，但应用概念与社交平台混用，工作区菜单仍绑死小红书。
- 轻量应用注册（选定）：将应用元数据、入口与业务实现分开，保留小红书全部现有路由，改动边界清晰。
- 微前端：可以独立构建部署，但首期复杂度过高，会扩大现有系统的改动面。

这里的“应用”是独立业务工作台，不是社交平台。小红书运营是首个应用；现有抖音、快手等平台配置不自动成为应用注册项。

## 4. 架构与模块边界

### 4.1 应用注册层

新增独立的、前端静态维护的应用注册配置。首期无需数据库表或应用目录接口。

每个注册项包含：

- 唯一应用标识，例如 `xhs`。
- 展示名称“小红书运营”。
- 应用说明。
- 图标，使用现有图标依赖或本地资源，不请求外部资源。
- 入口路径，首期为 `/platforms/xhs/dashboard`。
- 是否启用。

注册层负责提供目录和安全解析已知应用入口，不加载小红书业务数据，不维护用户权限。启用状态仅是应用可用性配置，不代表授权。

现有社交平台注册、`PlatformMeta`、平台接口和平台配置保持不变；应用注册与它们使用不同的命名和类型。

新应用以后可在当前工程内声明自身路由与工作台布局，再在应用目录中注册入口。本期不构建动态插件加载、远程菜单或通用工作台引擎，也不强制新应用复用小红书菜单。

### 4.2 应用中心

新增受现有登录守卫保护的 `/apps` 页面：

- 品牌名称“超级工作台”。
- 应用选择说明。
- 当前登录用户与退出登录入口。
- 首期仅一张“小红书运营”卡片，点击进入已注册入口。
- 使用现有 Ant Design 组件和主题体系，响应式排列，不新增 UI 依赖。
- 应用名称与说明使用普通 React 文本渲染，不注入 HTML。

不新增跨应用统计、任务聚合、收藏、搜索、最近访问或应用管理后台。

### 4.3 小红书工作台适配

继续使用现有 `AppShell` 与原有业务路由。仅允许调整其应用身份展示与返回导航：明确当前为“小红书运营”，增加可辨识的“应用中心”入口，指向 `/apps`。保留侧栏折叠后的可访问入口。

不重新排列、删减或重命名现有业务菜单；不更换现有布局、页面内容、通知逻辑或缓存配置。不抽取或重写小红书业务组件。已有 `PageHeader` 等导出保持兼容。

## 5. 导航与数据流

### 5.1 路由规则

| 访问情形 | 目标行为 |
| --- | --- |
| 访问 `/` | 跳转 `/apps`；若未登录，由现有守卫引导至登录页 |
| 成功登录 | 始终进入 `/apps`，不使用原 `from` 自动进入业务页 |
| 注册成功并建立会话 | 与登录成功一致，进入 `/apps` |
| 已登录访问 `/login` | 跳转 `/apps` |
| 已登录访问 `/apps` | 展示应用中心，即使只有一个应用也不跳过 |
| 已登录点击小红书应用 | 进入 `/platforms/xhs/dashboard` |
| 已登录直接访问或刷新现有小红书业务地址 | 原页面正常加载，不强制重新选择应用 |
| 未登录直接访问业务地址 | 进入登录页；登录成功后先进入 `/apps` |
| 访问 `/platform-select` | 保留兼容重定向至 `/apps`，使用 replace 避免返回循环 |
| 小红书工作台返回应用中心 | 进入 `/apps`，不注销、不清空业务数据 |
| 退出登录 | 继续使用现有退出和守卫行为，不建立第二套会话处理 |

“登录后先选应用”只约束建立新登录会话后的落点，不要求每次刷新业务页面都重新选择。

原有其他 `/platforms/*` 占位路由保持现有行为，不借此改造社交平台模块。

### 5.2 应用入口与异常

为应用入口定义受登录保护的 `/apps/:appId` 解析路由：已注册且启用的应用跳转其配置入口；未知应用或不可用应用展示明确提示及返回应用中心的操作，不回退到小红书冒充有效应用。

应用中心正常卡片可使用这一解析入口。禁用应用卡片如未来被注册则显示不可用状态且不可点击；首期不注册禁用占位应用。解析路由不包围或拦截 `/platforms/xhs/*`，不改变小红书原有 fallback 路由。

### 5.3 数据与认证

1. 应用中心读取现有 `useAuth` 中的用户信息。
2. 应用目录读取本地注册配置，不依赖现有 `/platforms` 请求。
3. 用户进入小红书后，页面继续调用原接口；Token 和用户数据归属完全沿用原实现。
4. 登录过期、刷新失败、凭证清理及错误展示沿用现有实现，不增加新的 token 或存储项。
5. 应用状态不写入现有业务表，不在小红书接口中新增 `app_id` 参数。

## 6. 公共能力的首期归属

任务中心、模型配置、设置和通知保持目前入口、呈现方式、接口及数据范围。首期不把它们搬到应用中心，不按应用重新过滤任务或通知，也不拆分模型配置。

这是一项兼容性约束，而不是承诺所有后续应用自动共享这些业务数据。后续应用需要公共能力时，另行设计其数据范围与接入方式。

## 7. 改动与禁止改动范围

### 允许

- 新增前端应用类型、注册配置及入口解析。
- 新增应用中心与应用不可用提示页面。
- 调整根路由、登录后落点、公共登录守卫的已登录跳转和旧选择页兼容入口。
- 对现有 `AppShell` 做最小的应用身份及返回入口调整。
- 新增针对上述行为的测试或验证材料。

### 禁止

- 修改 `frontend/src/pages/platforms/xhs/` 下的业务页面。
- 修改小红书功能菜单对应路径、原组件绑定与缓存规则。
- 修改后端 API、服务、模型、迁移、调度器或 SDK。
- 修改现有平台配置与其后端注册逻辑。
- 修改任何业务表及其已有数据。
- 引入应用授权、RBAC、组织租户、独立部署或插件市场。
- 顺带修复或重构无关模块；如发现阻断问题，应记录并告知用户，不擅自扩大范围。

## 8. 验收与验证

### 导航验收

1. 未登录访问 `/`、`/apps`、`/apps/xhs` 或小红书深链接时，均受现有认证守卫保护。
2. 登录或注册成功后总是先展示应用中心，包括带原业务 `from` 的情形。
3. 应用中心只有真实可用的小红书应用；点击后进入原总览。
4. 已登录刷新小红书深链接不会被门户拦截。
5. 工作台可明确返回应用中心，退出登录继续有效。
6. `/platform-select` 仍可使用且没有重定向循环。
7. 未知或不可用的应用入口显示明确提示，不错误进入小红书。

- 核对所有现有业务路由与组件绑定，包括总览、账号矩阵、数据洞察、笔记发现、数据抓取、关键词组、内容库、草稿工坊、竞品监控、图片工坊、视频工坊、发布中心、自动运营及原 section fallback。
- 任务中心、模型配置、设置的地址与组件绑定不变。
- 笔记发现与数据抓取的 KeepAlive 配置不变；在小红书工作区内切换页面时继续维持原行为。不新增离开整个工作区后仍保留内存缓存的承诺。
- 通知、主题切换、侧栏折叠及退出入口仍可使用。
- 通过最终改动清单确认小红书业务文件和后端文件未被修改。

### 工程验证

- 执行前端 TypeScript 检查与生产构建，确认结果。
- 执行已有后端测试，记录实际结果；若环境不满足或既有测试失败，应如实说明，不将其视为通过，也不擅自修改后端。

- 不执行真实平台采集、发布、账号绑定、外部模型调用或定时任务触发。
- 构建与测试通过仅证明已覆盖的范围，不声称已实测所有外部小红书功能。
