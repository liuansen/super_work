## 1. 目标与确认结论

在现有超级工作台内新增独立的「剪辑工坊」应用，把 OpenCut 作为独立的视频编辑器接入，形成平台无关的成片能力：

**素材选取 → 进入编辑器 → 素材拼装剪辑 → 导出成片 → 回传工作台 → 送入小红书草稿或抖音发布中心。**

已确认的产品决策：

1. 核心目标是打通「采集 → 剪辑 → 发布」的成片闭环，不是只加一个孤立的剪辑工具入口。
2. 剪辑能力由小红书和抖音共用；不把剪辑器做成某一个平台的子页面。
3. 首期能力按素材拼装型验收：多段视频/图片拼接、裁剪首尾、背景音乐、字幕/标题、封面帧、导出 MP4。
4. 允许为编辑器单独部署一个服务/容器；不要求塞进现有 Vite 工程。
5. 剪辑工程首期只在浏览器本地保存；工作台保存素材会话、成片文件和元数据。工程服务端化与跨设备续编属于二期。
6. 现有小红书、抖音的业务页面、接口、数据范围和调度行为保持不变；只做发布链路所需的素材前缀兼容。

## 3. 方案选择

采用「独立编辑器服务 + 素材/成片桥接」。不采用源码级移植，也不采用自研轻剪辑器作为首期方案。

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A. 独立服务 + 桥接 | fork OpenCut 单独部署；工作台通过一次性令牌下发素材、接收成片 | **选定**。保留上游时间线与 UI，升级边界清晰，风险最低 |
| B. 源码级移植 | 去掉 Next.js 外壳，改造成 Vite 可挂载模块 | 不选。改造量大，Tailwind/shadcn 与 Ant Design 两套体系冲突，长期与上游分叉 |
| C. 自研轻剪辑器 | Ant Design 时间线 + FastAPI 调 ffmpeg 合成 | 不选。等于重做 OpenCut 的核心价值，前端时间线交互与渲染队列成本高；仅在 M0 证伪方案 A 时作为备选重新评审 |

首期不采用 iframe 内嵌：编辑器在新标签页打开。这样避免 iframe 的存储分区、全屏、剪贴板、下载权限限制；工作台负责会话创建、状态与成片库，编辑器负责编辑。iframe 内嵌留待后续评估，不作为首期验收项。

## 4. 范围与非目标

### 4.1 首期范围

1. 新增独立应用「剪辑工坊」，应用标识 `clip`，路由 `/clip`。
2. 应用中心新增「剪辑工坊」卡片；小红书和抖音工作台菜单各增加一个入口。
3. 小红书原「视频工坊」占位页改为跳转入口：`/platforms/xhs/video-studio` → `/clip?from=xhs`，保留原路由与菜单项。
4. fork OpenCut 并固定提交，提供独立 Dockerfile 与容器编排；只在 fork 内增加工作台相关的导入、回传、返回入口和会话错误提示。
5. 素材选择来源：
   - 内容库笔记已下载到本地的图片和视频；
   - 草稿中已有的图片和视频素材；
   - 用户本地上传的图片、视频、音频。
6. 素材会话：一次会话可携带多个素材，素材清单在创建时快照。
7. 成片回传：导出 MP4 后上传工作台，成片库持久保存并支持预览、下载。
8. 成片去向：
   - 小红书：创建草稿并写入视频素材，后续沿用现有草稿与发布中心；
   - 抖音：跳转发布中心并预选成片文件与标题，发布仍走现有「创建意图 → 显式执行」流程。
9. 失败可恢复：素材缺失、令牌过期、上传中断、编辑器不可用均有明确提示和重试路径。

### 4.2 非目标

- 服务端保存可编辑工程、跨设备续编、工程版本历史。
- 多人协作、评论、审片、权限分级。
- AI 自动成片、TTS 配音、自动字幕、智能剪辑。
- 修改现有小红书/抖音业务接口、数据范围、发布流程或定时任务。
- 移动端编辑；首期只保证桌面浏览器。
- 面向外部用户的公开剪辑器或独立注册体系。
- 在剪辑器内直接发布到平台；发布始终回到工作台现有流程。
- 会话恢复：关闭编辑器标签页或握手令牌过期后，不提供「继续上次会话」；用户返回工作台重新创建会话，已导出的成片不受影响。本地工程仍在浏览器中，但首期不建立它与新会话的自动关联。

### 5.1 组件

| 组件 | 职责 | 建议位置 |
| --- | --- | --- |
| 剪辑工坊前端 | 素材选择、会话创建、打开编辑器、成片库、送入草稿/发布 | `frontend/src/features/clip/` |
| 工作台 API | 资产目录、会话与令牌、素材流式读取、成片上传、草稿对接 | 新增 `backend/app/api/clip.py`、`backend/app/clip/` |

| 媒体存储 | 复用 `backend/app/storage/media`；成片前缀 `xhs-clip-u{uid}-` | 现有存储 |

### 5.2 边界规则

1. 身份、授权、文件归属和发布逻辑只在 FastAPI 内实现；编辑器不保存工作台账号凭据。
2. 编辑器只通过两个接口与工作台交互：拉取本次会话素材、上传导出成片。其余编辑行为完全在编辑器本地完成。
3. 工作台不解析、不修改 OpenCut 的工程格式；工程数据首期不离开浏览器。
4. 现有 `AppShell` 与 `DouyinShell` 只增加菜单入口，不改业务菜单顺序和页面内容。
5. 应用注册继续使用静态前端配置，不引入数据库应用表或动态插件加载。

### 5.3 部署

- `docker-compose.yml` 新增 `editor` 服务，使用 fork 的镜像；默认仅绑定回环地址。
- 工作台通过配置项 `CLIP_EDITOR_PUBLIC_BASE_URL` 生成新标签页地址；开发环境可指向 `http://127.0.0.1:<port>`。
- 跨域只开放 `/api/clip/*`，Origin 白名单由 `CLIP_EDITOR_ALLOWED_ORIGINS` 配置，不使用通配符，不使用 Cookie，只接受 `Authorization` 头。
- 对外部署时由反向代理提供 TLS；编辑器与工作台可以不同源，不要求同一域名。
- 新增配置项：`CLIP_EDITOR_PUBLIC_BASE_URL`、`CLIP_EDITOR_ALLOWED_ORIGINS`、`CLIP_MAX_EXPORT_BYTES`（默认 2GiB）、`CLIP_SESSION_TTL_HOURS`（默认 12）、`CLIP_MAX_ACTIVE_SESSIONS`（默认 3）、`CLIP_USER_EXPORT_QUOTA_BYTES`。全部写入 `.env.example` 并在 README 说明。
- 若 M0 证明 OpenCut 的请求层无法附加 Authorization 头，或 Range/CORS 不可用，则改为「编辑器服务端代理」：浏览器只访问编辑器同源接口，由编辑器服务端转发到工作台。接口约定、数据模型和前端流程不变，仅增加代理层。

## 6. 握手与数据流

### 6.1 创建会话

`POST /api/clip/sessions`

请求：

```json
{
  "title": "新品开箱视频",
  "assets": [
    {"kind": "note_asset", "id": 123},
    {"kind": "draft_asset", "id": 45},
    {"kind": "upload", "file_name": "xhs-upload-u1-abc.mp4"}
  ]
}
```

规则：

- `title` 1–120 字符。
- `assets` 1–50 项，去重后保持用户选择顺序。
- 每一项都必须属于当前用户、文件在媒体目录内且真实存在；远程未下载素材不接受，前端提示先下载。
- 服务端把解析后的文件名、类型、大小写入 `manifest_json` 快照，后续会话不再重新解释用户输入。
- 返回 `session_id`、`editor_url`、5 分钟一次性 `handoff_token`、`handoff_expires_at`。
- 同一用户同时处于 `issued`/`exchanged` 状态的会话默认上限 3 个；超限返回 409 并提示先完成或放弃旧会话。

### 6.2 打开编辑器并交换令牌

前端在新标签页打开：

```text
{editor_url}#handoff={handoff_token}&session={session_id}
```

令牌放在 fragment，不进入服务端访问日志和 Referer。

编辑器加载后调用：

`POST /api/clip/sessions/{id}/exchange`

- 请求头：`Authorization: Bearer <handoff_token>`。
- 校验签名、作用域、用户、会话、有效期和未使用状态。
- 成功后把会话置为 `exchanged`，记录 `exchanged_at`。
- 返回 `CLIP_SESSION_TTL_HOURS`（默认 12 小时）有效的 `session_token`、素材清单（文件名、类型、大小、下载路径）和 `session_expires_at`。
- 重放已交换的令牌返回 409；过期返回 410。
- 编辑器读取 fragment 后立即用 `history.replaceState` 清除地址栏中的令牌，再把会话信息保存在内存中；刷新编辑器页面需要重新从工作台进入。

### 6.3 素材下行

`GET /api/clip/sessions/{id}/assets/{file_name}`

- 请求头：`Authorization: Bearer <session_token>`。
- 只允许 `manifest_json` 中的文件名；再次校验归属前缀与路径安全。
- 支持 HTTP Range（206），供视频预览与分段读取。
- 响应头使用 `private, no-store`，不写公共缓存。
- 单个素材缺失返回 404，不泄露服务器路径。

### 6.4 导出回传

`POST /api/clip/exports`

- 请求头：`Authorization: Bearer <session_token>`。
- `multipart/form-data`：`file`、`title`、`client_export_id`（编辑器生成的幂等键）、可选 `duration_ms`。
- 流式写入临时文件，超过 `CLIP_MAX_EXPORT_BYTES`（默认 2GiB）立即中止并删除临时文件。
- 只接受 `.mp4`（首期）并校验文件头，客户端声明的 MIME 不作为依据。
- 服务端生成文件名 `xhs-clip-u{uid}-{uuid}.mp4`，原子改名为最终文件后写入 `clip_exports`。
- `(session_id, client_export_id)` 幂等：重复上传返回已存在的成片记录，不产生第二份文件。
- 首次成功导出把会话置为 `completed`，但 `session_token` 在过期前仍可继续导出多个版本。
- 超过用户成片配额时返回 413 或 409，并给出可读提示。

`GET /api/clip/exports?limit=...`

- 返回当前用户成片，按创建时间倒序，`limit` 默认 50、最大 200。
- 每项包含标题、文件名、大小、时长、创建时间、下载地址、是否已关联草稿。

`DELETE /api/clip/exports/{id}`（M3）

- 未关联草稿时删除记录与文件；已关联返回 409。

### 6.5 成片去向

小红书：

`POST /api/clip/exports/{id}/draft`，请求 `{"platform": "xhs"}`。

- 复用现有草稿与素材服务，创建标题取自成片的草稿，并写入一条 `DraftAsset(asset_type="video", local_path=file_name)`。
- `clip_exports.linked_draft_id` 记录关联；重复调用返回同一草稿，不重复创建。
- 之后由用户在草稿工坊继续编辑并进入发布中心。

抖音：

前端跳转 `/platforms/douyin/publish?media={file_name}&title={title}`。

- 发布页读取查询参数，预选该视频并填充标题。
- 只做预选；用户仍需选择账号、可见性并显式创建和执行发布意图。
- 若发布页无法读取参数或文件被清理，给出提示，不静默丢弃。

### 6.6 素材目录

`GET /api/clip/assets?q=&type=&source=&limit=`

- 汇总当前用户可用的本地素材：笔记已下载素材、草稿素材、本地上传。
- 只返回文件真实存在的项；`source` 取 `note`、`draft`、`upload`。
- 返回可用于选择的稳定标识、文件名、类型、大小、缩略图/预览地址（若已有）和来源说明。
- 不返回服务器绝对路径；跨用户数据不可见。

## 8. 安全

1. 握手令牌 5 分钟有效、一次性、入库存 `jti`、绑定用户与会话；会话令牌默认 12 小时有效（可配置）、仅限该会话。
2. 两种令牌使用现有签名机制但使用独立作用域（`clip:handoff`、`clip:session`），不能用于其他 API。
3. 令牌通过 URL fragment 传递；日志、错误信息、监控标签中不得出现令牌或签名 URL。
4. 素材读取只接受 manifest 内文件名，并再次执行归属与路径校验；禁止目录穿越。
5. 上传执行扩展名与文件头双校验、流式写盘、失败清理、原子改名；文件名完全由服务端生成。
6. 每个用户同时活跃会话数、单文件大小、成片总容量均可配置；超限返回明确状态码。
7. CORS 使用精确 Origin 白名单；不开放 Cookie 凭据；只允许 `GET/POST/DELETE` 和 `Authorization`、`Content-Type` 头。
8. 编辑器容器默认绑定回环地址；公开访问必须经过反向代理和 TLS，与现有应用部署约定一致。
9. 过期会话 7 天后清理；上传临时文件超过 24 小时清理；清理任务不触碰成片文件。
10. 发布仍由用户在工作台显式执行，剪辑工坊不持有平台 Cookie，不直接调用平台发布接口。

## 9. 错误处理

| 场景 | 服务端行为 | 用户可见行为 |
| --- | --- | --- |
| 素材不属于当前用户或不存在 | 400/404，不返回路径 | 选择列表中该项不可用并说明原因 |
| 素材未下载到本地 | 400 | 提示先到内容库下载 |
| 会话数超限 | 409 | 提示完成或放弃旧会话 |
| 握手令牌过期 | 410 | 编辑器提示返回工作台重新进入 |
| 握手令牌重放 | 409 | 同上，不重复交换 |
| 会话令牌过期 | 401 | 编辑器提示重新进入；已导出本地文件仍可保留 |
| 素材流读取失败 | 404/500 | 编辑器标注失败素材，可重试或移除后继续 |
| 成片超过大小/类型不符 | 413/400 | 显示上限与支持格式，不落盘 |
| 上传中断 | 清理临时文件 | 编辑器保留本地导出并可重试 |
| 重复点击导出 | 幂等返回 | 成片库不出现重复记录 |
| 编辑器服务未启动 | 前端无法加载 | 剪辑工坊显示检查服务与重试入口 |
| 已关联草稿的成片被删除 | 409 | 提示先解除草稿引用 |
| 抖音发布预选参数失效 | 不影响发布页 | 提示重新选择成片 |

7. 用户 B 无法读取用户 A 的会话、素材和成片；过期或重放令牌被拒绝。

## 12. 风险与待验证项

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 许可证不允许当前使用方式 | 方案不可用 | M0 闸门，必要时改用方案 C 并重新评审 |
| OpenCut 无法加自定义请求头或 CORS/Range 不满足 | 桥接不可行 | M0 验证；回退编辑器服务端代理，接口不变 |
| 上游版本快速变化 | 补丁维护成本 | 固定提交，桥接改动集中在独立目录，记录补丁清单 |
| 浏览器存储容量不足 | 大工程无法保存 | M0 记录容量；限制单会话素材总大小；二期服务端化 |
| 大文件上传占用磁盘/带宽 | 成本与失败率 | 独立上限与配额、流式写盘、临时文件清理 |
| 两套 UI 风格不一致 | 体验割裂 | 工作台只做入口与成片库；编辑器保持独立工作区 |
| 本地工程与会话解耦 | 关闭标签页后无法从旧会话继续 | 首期明确提示重新创建会话；二期工程服务端化时再设计恢复 |
| 编辑耗时超过会话有效期 | 导出无法回传 | 默认 12 小时并可配置；编辑器在上传失败时保留本地文件并提示重新进入 |
| 编辑器服务暴露到公网 | 未授权使用 | 默认回环绑定，公开部署必须反向代理和 TLS |
| 跨用户素材泄露 | 安全事件 | 所有接口归属校验、manifest 白名单、跨用户测试 |
| 抖音/小红书前缀校验遗漏 | 成片无法发布 | 统一加入 `xhs-clip-u` 并覆盖测试 |

**未验证事实**：本设计编写时无法访问外网，OpenCut 的许可证、具体版本、导出能力、可扩展点和运行要求均未核实。M0 结束前，不得把上述内容当作既定能力对外承诺。
